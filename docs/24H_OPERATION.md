# 24時間運用の決まり

このリポジトリで、DeepSeek と GLM が人の指示なしに動き続けるときの運用の決まりです。依頼者の指示（2026-10-16）に基づきます。

## 1. 目的
- 対価を払う人がいるくらいの品質のプログラムを、しっかり作る。
- 動画制作から枝分かれして、金銭が発生する別プロジェクトも実施してよい。
- リポジトリの他のファイルを、多機能に育ててよい。

## 2. 許可
- 課金と停止を除き、何をしてよい。
- ファイルの作成と編集、コマンド実行、パッケージの導入、Web 検索、外部ツールとプラグインの導入、外部 API の無料枠の利用を含む。
- 新しい VM では、OpenCode の権限は `allow`（課金と停止を除く）。

## 3. 禁止
- 課金: 有料プランへの加入、クレジットの購入、有料モデルへの切替。
- 停止: VM、サービス、他ジョブ、Desktop Commander の停止や再起動。
- 公開: YouTube、SNS、公開ページ、Drive の共有リンクなど、外部に公開する操作。
- 認証情報の表示やコミット（鍵、トークン、Cookie、`auth.json`）。
- main への直接 push、PR の承認とマージ。

## 4. 1 サイクルの流れ
1. 課題を選ぶ（前のサイクルの `vote.md` や `log.md` を参照）。
2. 設計と実装、またはテストを行う。
3. 検証する（テストや検査スクリプト）。客観的な結果だけを採用根拠にする。
4. 結果を `logs/<日付>/<ジョブID>.md` に残す。失敗の出力は消さない。
5. 採用した改善を `CHANGELOG.md` に 1 行で追記する。

## 5. 記録
- 作業フォルダの中で完結させる。他の参加者のフォルダは読むだけ。
- ログは追記だけ。前の記録は消さない。
- 外部から得た情報には出典を付ける。公式情報で確認できない数字は、確認済みと書かない。

## 6. 議論の進め方（10体）
- 提案は `proposal.md`、批判は `critique.md`、結論は `vote.md`。
- 決定は合議。依頼者の逐次指示は待たない。

## 7. 異常時の扱い
- 同じ失敗が 3 回続いたら、そのサイクルを止めて理由を残す（停止はサイクル単位で、サービスやVMは止めない）。
- 無料枠の上限やエラーが続く場合は、記録して次のサイクルに回す。課金に切り替えない。

## 8. 依頼者の役割
- 目標と憲章の変更、外部公開、課金の判断。
- 指示文（brief）の作成と更新。
