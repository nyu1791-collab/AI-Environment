# 動画制作ノウハウ（正本の要約）

出典: `docs/news_v2_process.md`（現行の正本、VM 側にあり取り込み待ち）と `docs/rules_changelog.md`（統合済みの案内のみ）。
ここには、依頼者が示した要点をまとめています。規則番号（R〜）は正本の番号です。

## 1. 全体像
- 流れ: 台本 → 素材表 → 音声（GPU）と素材（CPU）を並列 → 統合（描画）→ 版の検査 → Drive 保存。
- 台本と素材表は同時に作る。素材表の検査に合格するまで素材の取得は始めない（R29）。
- 現行の最新版は v12_speed115（音声 1.15 倍、1280×720、231.31 秒、6,940 フレーム）。Drive 保存済み。
- v13 は提示データのみ準備済み。動画は依頼者の指示で未作成。
- 制作スクリプト（make_speed.py、run_video.sh、check_version.py、check_rules.py など）は VM 上にあり、このリポジトリにはまだ無い。

## 2. 工程と担当
| 工程 | 入力 | 出力 | 完了条件 |
|---|---|---|---|
| A 音声（GPU） | 承認済みの台本（`z|` / `m|` 形式、URL なし） | 音声一式 | 承認済み音声を再利用、新台本のみ合成 |
| B 素材（CPU） | 素材表の項目 | スクショ、切り抜き、manifest | 切り抜きがすべて見つかり、エラー 0 件 |
| C 統合（CPU） | 音声、timing、presentation、素材 | 最終動画と QA（render/qa/） | フレーム数と長さが一致し、検査が PASS |
| 保存 | 最終動画 | Drive（drive-send） | `verified=true` を確認してから報告 |

- A と B は並列（R28）。C は A と B の後に 1 回だけ行う。
- 各工程は RUNNING / OK / WAIT / FAIL を status に書き、所要秒を残す。失敗の出力は消さない（R21）。

## 3. 版の作り方（R51）
1. `build_v5.py`: 台詞の時刻、強調語、表の効果音、章カードを作り、内容の契約を通す。
2. `make_speed.py <倍率> <版>`: 音声を atempo で変え、字幕、効果音、章カード、台本の時刻を同じ倍率で縮める。manifest.json を書く（R36）。
3. `run_video.sh <版のフォルダ>`: 事前検査、描画（直接符号化、1 スレッド）、効果音の合成、多重化、フレーム数の検査。
4. `check_version.py`: 章カードの montage、表の瞬間の画像、強調の拡大、音量、効果音の位置を render/qa/ に出す。
5. `check_rules.py`: R40〜R56 を機械判定し、render/qa/rules.json に書く。
6. 見直し: QA の画像を実際に見て、反省点を §8 に書く（R49）。
7. 保存: 作ったらすぐ drive-send（R50）。FAIL の項目は保存報告に併記する（R51）。
- 版は `versions/<版>/` に入れ、既存の出力は上書きしない（R37）。

## 4. 台本
- 形式: `z|`（ずんだもん）と `m|`（四国めたん）の 1 行ずつ。URL は入れない（R34）。
- 第 N 章の宣言は「第N章、〇〇なのだ。」の形（R39）。6 章が音声つきの章カードに対応。
- 初心者向けに、やさしい言葉で始め、後で詳しく足す。1 場面の解説は一段階まで（R31）。
- 前置き、注意事項、メタな説明は書かない（R31）。
- `[表]` は表が出る行、`[重要]` は重要な文、`[画像]` は画像が変わる行。重要な文は 4 語以内（R33、R56）。
- 台本本文に出典 URL や一覧は入れない。出典は作業記録（この文書と素材表）に残す（R34）。

## 5. 素材（スクショと切り抜き）
- 公式ページのスクリーンショットは毎回新しく取得。画像の再利用はしない（R18）。
- 素材表は material-sheet-v1 の JSON。各項目に公式 URL、対象名、切り抜き名、最大の高さ、行の境で分割するか、権利を書く（R29）。
- 全場面にスクショか切り抜きを 1 つ以上置く（R30）。
- 切り抜きは説明部分だけ。全文とみなす高さは 2,500 px 以上（R46）。切り抜きの高さは 700 px 以内（R54）。表は行の境で分ける。
- 公式スクリーンショットは内部確認用。公開前に権利を確認（R12）。
- AI 生成の画像は、依頼者が経路を決めるまで作らない（R11）。
- 海外の出典や英語の原文は、画面下段に日本語訳の帯を出す（30 字以内、R41、R53）。訳のない海外の出典は使わない。

## 6. 音声
- 承認済みの音声を再利用。新しい台本のときだけ Colab で合成（R10）。
- 速さは 1.15 倍。ピッチは atempo で保ち、字幕、効果音、章カード、台本の時刻を同じ倍率で縮める。元の音声と時刻は変えない（R36）。
- Colab GPU の起動は、SHA-256 が一致する音声一式（voice_pack_vN）に限る。起動前に `colab_owned_ops.py snapshot` で残存ランタイムがないか確認（R16、依頼者の監視は要件から撤廃済み）。
- 話者の形式は `z|` / `m|`。`KeyError('[scene_01')` は形式の誤りで起きた失敗の例。

## 7. 効果音
- 効果音は自作。出典は示さない（R35）。名前とファイルの対応は `assets/sfx/sfx_table.json`。
- 表が出る瞬間に「ドドン」、表を切り替えるときに「シュ」（`se_events` で時刻指定、R32）。
- 章カードの間には鳴らさない。カードの終わり（表が見え始める時刻）に置く。`make_speed.py` が移す（R55）。
- 画像が切り替わるときはめくる音「シュ」を必ず付ける。章カードの間はカードの終わりに置く（R52）。
- 位置の判定は、今は音量の比で確かめている。発話の強い所では外れるため、波形の相関による判定が必要（未解決）。

## 8. 字幕、マーカー、強調
- 重要な文は淡い黄（#FFE98A 付近）の帯で示し、語は字幕色の一段階濃く（字幕色 × 0.8）（R33、R42）。
- 強調語は timing の `caption_emphasis_terms` に書く。描画は `draw_caption_compact`（compact_v18）（R38）。
- 教訓: 使われない分岐に書いた強調は、全編で出なかった（v5、v6）。変更は実際に使われる描画経路で確かめる。
- 字幕は 36 px 以上（R13）。章の宣言の字幕は出さない（依頼者の決定、R39）。
- 1 文のマーカーは 4 語まで。数字の列は全部はマークしない（R56）。

## 9. 章、キャラクター、献立
- 章の切り替えは主題（sections の `is_main`）ごとに入れる（R44）。音声つきの章カードは 6 つ。
- キャラクター（ずんだもん、四国めたん）は画像が切り替わるたびに、画面上端から交互に顔を出す（約 1.9 秒、R45）。
- 献立（進行表示）は、完了した章に緑のチェック、現在の章に緑の枠と太字、未了はグレー。黒の塗りつぶしはしない（R47）。
- 献立の項目名は 2 行以内、文字は 15 以下に揃える。閉じ括弧や句読点だけを行頭に置かない（R47）。
- 画面は 1280×720 向け。献立は 4 倍で描いて縮める（R48）。

## 10. 描画と符号化
- 本番は「一本の描画 → 直接符号化（中間ファイルなし）」が既定（R2）。
- 分割描画（8 区間）は全フレーム不一致（区間 2〜7 で合計 313 フレーム）で不合格。使わない。
- 符号化は画質優先（OUT_PRESET=fast、OUT_CRF=20）。1 スレッド固定（DIRECT_THREADS 既定 1）。8 スレッドは実行ごとに映像が変わったため不採用（R8）。
- 口の判定、音声の位置、画面の状態は全編の時刻（フレーム番号）で計算（R6）。
- 映像の変更は MD5 の一致で確かめる（同じ区間、1 スレッド、R20）。
- フレーム数の期待値は `ceil(長さ × 30)`（R13）。
- 実測（参考）: v12（231.31 秒）の描画は約 81〜84 秒（1280、fast、CRF 20、1 スレッド）。

## 11. 検査
- `check_rules.py`（v12）: R40〜R46、R55、R56 が PASS。R47 は未機械判定（目視 PASS）。R53（訳の帯 30 字以内）と R54（切り抜きの高さ）は FAIL で、v13 の提示データで解消予定。
- `check_version.py`: フレーム数、音量（v12 は −18.3 LUFS）、章カードの montage、マーカーの画素数（v12 は 6,547 画素）を出す。
- 未実施: 字幕の箱のはみ出し（R13）、耳による音の確認（効果音、速度）、PROD の 360p の字幕実測。
- 検査していない項目は「未実施」と書く（R13）。

## 12. 保存と版管理
- 作ったらすぐ Drive へ（`drive-send --name`、`verified=true` を確認）（R50）。
- 保存済みの版: v9、v10、v12（Drive の ID は正本の §12 を参照）。
- 版番号は v4〜v13（§7）。失敗した版（v4、v5、v6、v8）は ❌ で残す。

## 13. 運用と権限
- 制作 VM は `instance-20261001-071545`（8 vCPU）。中継ノードは `dc-control-node`。VM の停止と変更は中継から行う（R17）。
- 権限は範囲を決めて与える。`--auto` と `--dangerously-skip-permissions` は使わない（R22）。
  - 注: 2026-10-16 の依頼者の指示で、新しい VM では課金と停止以外の権限を与えている。この点は `docs/24H_OPERATION.md` に記す。
- コードの修正は見張り役（Claude）だけが行う。実行役と作業役はコードを書き換えない（R23）。
- 作業役（DeepSeek）は作業場所の中だけで動く。出力が空なら失敗とし、1 回だけやり直す（R26）。
- Desktop Commander は 1 回の呼び出しで複数の確認をまとめる（R59）。
- 公開（R1）、外部への送信、課金、削除は依頼者の確認を得てから。

## 14. 失敗と教訓（抜粋）
- 使われない経路に機能を書いた: 強調が出なかった（R38）。
- 音声を変えたのに時刻が古いまま: `make_speed.py` が全時刻を同じ倍率で変えるようにした。
- 同じ出力の上書き: `run_video.sh` は既存の `video.mp4` を見つけたら止まる（R37）。
- 表の効果音が章カードの間に鳴った: カードの終わりに移した（R32）。
- 引用文に「判定: 合格」が含まれ、誤って合格扱いになった: 判定は出力の最後の行だけを見る。
- 長い待ちで利用量を使い切った: R59 に従う。
- 最低賃金ニュースの台本で、作業役 DeepSeek が「正しい」と判定した数字（鹿児島 1,090 円、12 年連続など）は、公式情報で確認できなかった。作業役の判定は、統合者が公式情報で必ず再確認する。
