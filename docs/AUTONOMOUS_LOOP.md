# 自立ループ（永続的な推論と改善）

エージェント(GLM と DeepSeek)が、人の指示を待たずに推論と改善を繰り返すための運用です。
依頼者が「停止」と言うまで続けます。上限の時間は設けず、サイクルを繰り返します。
前提の決まりは `docs/24H_OPERATION.md` と `AUTONOMY_CHARTER.md` に従います。

## 1. ループの基本
1. **観察**: 最新の状態を読む(`STATE.md`、直前のサイクルの `log.md`、他の参加者の `vote.md`)。
2. **課題の選択**: 最も価値が高く、検証できる課題を1つ選ぶ。
3. **推論と実装**: 課題を深く考え、小さく実装またはテストする。
4. **検証**: テストや検査で客観的に判定する。AI の自己評価は根拠にしない。
5. **記録**: 結果を `log.md` に追記する(成功も失敗も、理由とともに)。
6. **次の課題の導出**: 結果から、次に確かめる問いを1つ作る。
7. 1に戻る。

## 2. 永続化のための状態ファイル
各エージェントのフォルダに、次の2つを置きます。
- `STATE.md`: 現在の目標、直近の結論、未解決の問い。毎サイクル更新する。
- `log.md`: 追記のみ。前の記録は消さない。

サイクルが途切れても、`STATE.md` から再開できるようにします。

## 3. 継続の規則
- サイクルの終わりに、次の問いを必ず1つ書く。空にしない。
- 同じ課題が3回続けて失敗したら、課題を変える。ただし、その理由を `log.md` に残す。
- 完全に行き詰まったら、問いを立て直して新しいサイクルを始める。終了はしない。
- 他の参加者の成果を読み、批判、統合、改良の提案を出す。

## 4. 意欲の方向
- 目標: 対価を払う人がいる品質のプログラムを作る。
- 動画制作から枝分かれして、金銭が発生する別プロジェクトを探してよい。
- リポジトリの他のファイルを、多機能に育ててよい。
- 外部の検索やツールを使って、新しい知見を取り入れてよい。

## 5. 禁止(変わらず)
- 課金(有料プラン、クレジット購入、有料モデルへの切替)。
- 公開(YouTube、SNS、公開ページ、Drive の共有リンク)。
- 停止(VM、サービス、他のジョブ、Desktop Commander の停止や再起動)。
- 認証情報の表示やコミット。
- main への直接 push、PR のマージ。

## 6. 記録と共有
- 採用した改善は、リポジトリの `CHANGELOG.md` に1行で書く。
- 成果物は `council/<ラウンド>/<名前>/` に置く。
- push は、作業ブランチ `ccr-ca42f2ca-az6tdd` だけに行う。
